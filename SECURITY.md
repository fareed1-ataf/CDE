# Security Policy

## Supported Versions

| Version | Supported          |
|---------|--------------------|
| 3.1.x   | ✅ Active support   |
| < 3.0   | ❌ End of life      |

---

## Reporting a Vulnerability

**Do NOT open a public GitHub issue for security vulnerabilities.**

We take security seriously. If you discover a vulnerability, please report it privately using one of the following methods:

### Option 1 — GitHub Private Security Advisory (Preferred)
1. Go to the repository's **Security** tab on GitHub.
2. Click **"Report a vulnerability"**.
3. Fill in the advisory form with as much detail as possible.

### Option 2 — Email
Send a detailed report to the maintainer's email (listed in the GitHub profile). Include:
- A description of the vulnerability
- Steps to reproduce
- Potential impact
- Any suggested mitigations (optional)

## Response Timeline

| Stage                             | Target Time     |
|-----------------------------------|-----------------|
| Acknowledgement of report         | Within 48 hours |
| Initial triage and severity rating | Within 5 days   |
| Fix development and testing       | Within 14 days (critical) / 30 days (others) |
| Public disclosure (CVE if needed) | After fix is released |

## Scope

The following are **in scope** for this security policy:

- API key exposure through `config/providers.json` serialisation
- Arbitrary file read/write via path traversal in upload endpoints
- CORS misconfiguration allowing cross-origin attacks
- Race conditions in cache or output file writes that corrupt training data
- Authentication bypass on any API endpoint

The following are **out of scope**:

- Vulnerabilities in third-party LLM providers (Groq, OpenAI, etc.)
- Issues in models generated by the pipeline (hallucinated content)
- Denial-of-service by uploading very large files (known limitation)

## Security Best Practices for Self-Hosted Deployments

1. **Never expose the server on a public IP.** This tool is designed for local use only (`127.0.0.1`).
2. **Use environment variables for API keys.** Set `${GROQ_API_KEY}` etc. in your environment — never paste real keys into `providers.json`.
3. **Rotate API keys immediately** if you suspect `providers.json` was committed to Git history.
4. **Run `git filter-repo`** to purge secrets from Git history before pushing to any remote.
5. **Keep dependencies updated.** Run `pip install -r requirements.txt --upgrade` regularly.
